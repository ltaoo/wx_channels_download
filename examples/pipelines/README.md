# 创作者自动化 Pipeline

这些 JSON 使用当前项目的流程定义格式，可在「自动化 → 导入 Pipeline」中粘贴文件内容导入。默认面向微信视频号。

| 文件 | 功能 | 建议 Cron |
| --- | --- | --- |
| `01_creator_video_sync.json` | 通过 HTTP 接口逐页检查视频，直接用列表对象下载缺失视频，遇到整页已存在时停止 | `0 12,18 * * *`，每天 12:00、18:00（已内置） |
| `01_creator_video_sync_service.json` | 通过内置工具获取列表，其余增量检查与下载流程和 HTTP 版相同 | `0 12,18 * * *`，每天 12:00、18:00（已内置） |
| `02_creator_live_record.json` | 查询当前直播，正在直播时创建录制任务，未开播正常结束 | `*/1 * * * *`，每分钟 |
| `03_creator_new_video_notify.json` | 首次扫描建立基线，之后仅通知新增视频，使用企业微信机器人 | `*/5 * * * *`，每五分钟 |
| `download_finished_qiniu_webhook.json` | 下载完成后通过 JS 自定义节点上传七牛云，再发送原任务详情到 Webhook | 事件 `downloadtask.finished` |

七牛上传流程需要先安装 `examples/nodes/qiniu_upload.js`。JSON 包含 `downloadtask.finished` 默认事件触发器和 600 秒整体超时；新增实例后自动继承，填写七牛参数后即可响应下载完成事件。Webhook 支持在“配置”中设置 URL、method、headers、Bearer token 和 JSON body 模板。详见[安装与 Hook 迁移](../../docs/feature/pipelines/download-finished-qiniu-webhook.md)。

## 导入和配置

1. 按需导入 JSON，视频同步选择 HTTP 版或内置工具版。导入会生成新的 Pipeline ID。
2. 第一个流程在列表页「配置」中填写 `username`，并可设置列表接口 `url`、`method`、`token`；第二、三个流程仍在「配置」节点中修改 `creator_username`。username 推荐完整的 `xxx@finder`，它不是昵称，可以从账号搜索结果取得。
3. 前两个流程的 `download_dir` 留空时使用应用默认下载目录，也可以填写下载器所在机器的绝对路径。
4. 前两个视频同步流程已内置默认定时规则，导入后新增配置实例时自动继承。其余流程可在流程编辑页的开始节点添加默认定时规则，填写上表 Cron 并保存。实例“配置”中可像节点配置一样逐字段取消继承并填写覆盖值；例如只覆盖 Cron 时，超时与启停仍随流程默认配置更新。重新勾选字段的“继承流程配置”即可恢复继承。Cron 使用下载器进程的时区，调度器约每 30 秒检查一次。
5. 保持下载器运行。第一个流程需确保配置的 HTTP 列表接口可用，另外两个流程需确保视频号查询能力可用。首次运行可从定时规则的立即执行入口进行手动验证。

第一个流程通过子流程、`LoopNode` 和循环连线遍历分页及视频，直接把 HTTP 列表返回的完整视频对象交给 `create_download_task`，不会再查询详情或要求本机视频号页面建立 socket 连接。列表需包含媒体 URL、URL token 和加密视频所需的解密 key；仅返回 ID 无法直接下载。原流程需在编辑页重新导入 JSON 并保存才会使用修复后的模板。

HTTP 列表直接返回 `BaseResponse/object/continue_flag/last_buffer`，其中 `object_desc.media[].spec` 的 `file_format`、`duration_ms`、`video_bitrate`、`level_order` 会转换为下载器使用的画质字段。

`01_creator_video_sync_service.json` 以 HTTP 版为基准，仅把「获取创作者视频列表」替换为 `get_wxchannels_account_videos` 内置工具，并移除 HTTP 专用的 `url`、`method`、`token` 配置。导入后同样在流程「配置」中填写 `username`；运行时需要视频号查询能力可用。HTTP 版只解析原始下划线字段；内置工具版只解析 `errCode/data` 包装及驼峰字段，两版不兼容对方的响应格式。定时触发、分页、批量检查、整页已存在时停止、并行提交下载及下载结果统计完全相同，下载均通过 `create_download_task` 复用列表媒体，不再查询详情。

内置工具版在顶层 `subflows` 中声明分页、列表查询和单个视频下载子流程。`WorkflowNode` 和 `LoopNode` 使用 `config.flow_id` 引用声明的键，循环和遍历会重复执行同一份定义；子流程内也可引用顶层的其他子流程。保存的模板保留引用，创建执行记录时冻结依赖，保证重试使用当时的定义。详情页直接展开子流程容器，显示内部节点的实时状态和日志。

其余流程使用 JS、设置变量和条件分支回连遍历分页及视频。`max_pages` 默认 1000，`max_videos` 默认 100000；超过限制会明确失败，避免把截断结果当成全部内容。

## 新视频通知的额外配置

该流程默认对接**企业微信自定义机器人文本 Webhook**。

1. 导入并保存定时触发器后，获取该触发器的 ID（`sched-...`）。可请求 `POST http://127.0.0.1:2022/api/v1/automation/list_schedules`，请求体为 `{"flow_id":"导入后生成的 Pipeline ID"}`，从 `data.list` 取得对应规则的 `id`。
2. 将配置节点的 `monitor_schedule_id` 改为这个 ID。每个监控流程只配置一个定时规则，不要填写另一个 Pipeline 的规则 ID。
3. 将「发送企业微信机器人通知」节点 `config.url` 中的 `REPLACE_WEBHOOK_KEY` 换成自己的机器人 key。
4. 本地状态读取和保存节点默认使用 API 地址 `http://127.0.0.1:2022`。如果应用 API 地址或端口不同，同时修改这两个节点的 URL。2022 是 API 默认端口，2023 是代理端口。
5. 保存流程，先从该定时规则立即执行一次。首次运行只建立基线，不通知历史视频。之后出现新视频时，每条视频发送一条消息。

已知视频 ID 保存在该定时规则的 `initial_data.creator_video_monitor`，重启后保留。更新进度时保留现有参数及 `__automation` 元数据。每条消息成功发送并且企业微信返回 `errcode: 0` 后，才保存该条进度；部分通知失败时，后续运行只补发尚未确认的视频。

删除 `creator_video_monitor` 会在下次运行重新建立基线。更换创作者也会重新建立基线。编辑定时规则参数时，应保留最新的监控进度，避免旧表单覆盖新状态。不要让手动运行和定时运行重叠，或让多个流程共用同一个状态规则；当前接口没有跨运行的状态写入锁。

## 运行结果与边界

- 全量指平台接口当前允许访问的全部视频，不包含隐藏、已删除或无权限内容。分页游标缺失或重复、平台响应异常时会停止并报告失败，不会用部分结果建立通知基线。
- 同步流程创建并启动下载任务后继续处理下一条，`submitted` 不表示文件已经下载完成。实际文件结果在下载任务页面查看。`existing_action: "skip"` 跳过已有任务，也可能跳过已有失败任务；失败任务需要在下载任务中重试。
- 直播录制使用原生直播下载工具，以相同直播任务的 `skip` 策略避免每次轮询重复录制。它不等待直播结束；录制中断后的恢复仍需处理下载任务。平台在检查后刚好结束直播时，本次启动可能失败，下一次仍会重新检查。
- 通知按视频 ID 判断新增，而非按标题或发布时间。首次建基线后，接口后来才变得可见的旧视频也会视为新增。
- 通知采用至少一次语义：发送成功后、进度保存前发生崩溃，或发送请求超时但实际已送达，下一次可能重复发送。企业微信 Webhook 没有本流程可用的幂等确认接口。
- 修改 `creator_username`、通知 URL 等配置后先保存。通知流程的状态进度读取失败或保存失败会使本次运行失败，不会宣称成功。

## 非浏览器验证

在项目根目录运行：

```sh
go test ./pkg/flowengine/engine -run TestCreatorVideoSync
```

验证使用真实导入、保存、JS、分支、服务节点和 HTTP 节点，替换平台工具与 HTTP 传输返回模拟数据，不连接微信或发送真实通知。浏览器行为由用户导入后手动验证。
