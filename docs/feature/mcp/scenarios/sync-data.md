# 同步数据到另一台下载器

可以对 Codex 等 MCP 客户端说：

> 将本机已有下载同步到 NAS（192.168.0.118:2022）：重新创建下载记录和关联的内容、账号，把已下载文件上传过去，不重新下载，数据库 ID 不需要一致。

同步以下载任务为单位。源端读取已保存的任务输入；目标端复用普通“创建下载任务”的记录保存流程，创建任务、资源、内容、账号及其关联，随后安装上传的文件。整个过程不调用平台解析或下载器，不依赖原下载链接仍然有效。浏览记录、无关账号和无关内容不参与。

同步 Skill 内置在 MCP Server 中。Agent 可先调用 `get_sync_skill`，或通过 `resources/list` 找到 `dm://skills/sync-downloads`，再用 `resources/read` 读取其 `SKILL.md`。stdio 和 Streamable HTTP 提供相同内容。

源和目标都需要支持同步协议 v2。同步接收默认启用，无需设置 `sync.token` 或发送 Authorization 请求头，旧配置中的同步令牌不再参与校验。

源服务支持以下对话流程：

1. `get_sync_servers` 查看目标。没有 NAS 时，通过 `configure_sync_server` 传入 `name`、`url`；按名称添加或更新，立即生效，无需令牌。
2. 用户说“第一条”时，通过 `get_download_tasks` 的 `page=1,page_size=1` 获取当前列表第一条的 ID；指定记录时保持其 ID。用 `preview_sync` 的 `task_ids` 预览所选任务和文件，只读取本机数据，不上传文件。
3. 用户明确授权同步后，调用 `sync_to_server`，传入目标 `server_id` 和相同的 `task_ids`。全量同步必须显式设置 `all=true`，不能与 `task_ids` 同时使用。该工具启动后台任务并返回 `job_id`，不会因为当前对话请求结束就停止传输。
4. 使用 `get_sync_status` 查询 `job_id`，直到 `status=completed` 或 `failed`。只有 `completed` 表示目标的数据库事务及文件安装成功；结果包含各类记录、文件和字节数。

例如，已配置的 NAS 为第一个目标时：

```json
{"server_id": 0, "task_ids": [141]}
```

任务结果只在源进程内保留最近 20 条，重启后失效。任务丢失不能视为成功，应先核对目标数据。每个源进程同时只启动一个后台同步任务。

## 记录与文件的处理

- 任务、资源和内容详情中的自增主键由目标生成。内容、账号通过创建任务时的业务保存逻辑处理，资产和任务父子关系重新关联，不复制源端自增 ID。
- 下载记录保留源端的创建时间（毫秒精度），首次同步和重复同步均不会改为同步时间；缺失或无效的创建时间会导致导入失败。
- 新导入的内容和账号保留源端创建时间；按平台及业务标识匹配到目标端已有记录时，保留目标记录原有的创建时间，更新资料不会重置创建时间。
- 只携带任务及资源引用的内容、内容引用的关联内容和账号。内容详情、字幕、小说章节、图集、对话及资源资产关联通过原有创建任务的逻辑保存；不迁移整个数据库，也不复制浏览记录、标签库或独立的资源记录。
- 指定任务时不自动扩大选择范围。未选中的父任务不会自动加入，所选子任务在目标作为独立记录重建；任务不存在会返回错误，不会回退为全量。
- 内容和账号优先按平台及平台外部 ID 匹配。字符串主键被无关内容占用时，新记录会分配新的字符串 ID。下载任务按“平台、业务标识、原创建时间”识别同一次下载，保留重复下载的历史；重复同步同一份任务不会持续新增记录。
- 资源对应的现有文件、直播录制目录和播放目录会传输。目标将文件存入下载目录下稳定的 `synced/<资源目录>/` 子目录，同时更新资源记录中的目录和文件名，避免覆盖其他记录的同名文件。重复同步会替换同一同步资源的目标文件。
- 源端已完成的资源在文件上传并安装成功后保留完成状态。缺失文件或未完成的资源在目标端设为暂停，不会触发下载，也不会把没有收到文件的资源标为已完成。`.part` 不传输。
- 同步不复制运行中的连接和分片状态，不传播删除，不做双向合并。任务记录和文件安装在同一流程中提交，失败时回滚。
- 不复制应用配置、独立登录凭证库或 Cookie 文件。下载端点自身的请求参数、请求头和 Cookie 随该端点记录传输。

本机也保留手动入口 `http://127.0.0.1:2022/sync`。两种入口使用相同的数据打包与导入流程。

## HTTP 接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/sync/info` | 协议版本及是否启用接收 |
| GET | `/api/v1/sync/servers` | 目标列表，不返回令牌 |
| POST | `/api/v1/sync/servers` | 配置目标，参数为 `name`、`url` |
| GET | `/api/v1/sync/preview?task_ids=141` | 所选源数据量预览；不传参数时预览全部 |
| POST | `/api/v1/sync/servers/:server_id/jobs` | 启动后台同步，可传 `{"task_ids":[141]}` |
| GET | `/api/v1/sync/jobs/:job_id` | 查询后台同步状态 |
| POST | `/api/v1/sync/servers/:server_id` | 同步执行，完成后返回结果 |
| POST | `/api/v1/sync/import` | 直接接收 tar 数据包，无需令牌 |

接收端仍兼容协议 v1 的旧数据包，但旧包只包含原来的内容主表、下载任务、资源和文件。v2 源会先检查目标协议，目标版本过旧时拒绝传输，以免将不完整同步报告为成功。
