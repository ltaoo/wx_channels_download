# 自定义根证书

用于配置自定义证书与私钥。启用代理启动时，指定的证书必须可读、与私钥匹配、可用于签发且在有效期内；程序按 `proxy.skipInstallRootCert` 配置决定是否自动安装并验证系统信任。

## 配置键

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `cert.file` | `""` | 自定义证书文件的绝对路径，支持 `.pem`、`.cer`、`.crt`、`.key` |
| `cert.key` | `""` | 自定义私钥文件的绝对路径，支持 `.pem`、`.key` |
| `cert.name` | `"Echo"` | 证书名称，用于在系统证书库中识别、安装和卸载证书 |

## 示例（config.yaml）

```yaml
cert:
  file: "C:/path/to/mycert.pem"
  key: "C:/path/to/mykey.pem"
  name: "MyProxyCA"
```

## 生效规则

- `cert.file` 和 `cert.key` 必须同时配置，两个文件都可读，且证书与私钥匹配。
- 未配置 `cert.name` 时使用默认值 `Echo`。
- 启动时优先使用 `cert` 配置的证书；文件不可读、私钥不匹配、不可用于签发或已过期时直接报错退出，不会切换到其他证书。
- 未配置证书时，依次检查 mitmproxy、SunnyNet，仅复用证书与私钥匹配、已安装且受系统信任的证书；复用时不创建本机证书，也不写入 `cert` 配置。
- 新生成的自有根证书默认名称和颁发者均为 `wx_channels_download`，组织为 `dm.funzm.com`；已有证书需要重新生成并安装才会采用新身份信息。
- 未配置证书且没有可复用的受信任证书时，生成本机专属根证书并保存到工作目录的 `certs/` 下，按配置自动安装并验证信任成功后，将路径和名称写回配置，后续启动复用。设置 `proxy.skipInstallRootCert: true` 时直接保存配置，不安装证书。
- 已配置的证书不可读、格式无效或私钥不匹配会导致启动报错，请修复配置；有效配置始终优先使用，不会自动替换。
- `cert.file` 和 `cert.key` 应填写绝对路径。
- `proxy.skipInstallRootCert` 默认 `false`，配置证书或新建证书未受信任时自动安装，并在验证信任成功后启动；安装或验证失败则报错退出。设为 `true` 时跳过自动安装及系统信任校验，仍校验证书和私钥，使用 HTTPS 代理前需手动安装并信任。纯 `server` 模式或 `proxy.enabled: false` 不初始化代理证书。

## 注意事项

- 证书与私钥必须属于同一密钥对。
- `cert.name` 应与证书的通用名称（CN）一致，否则可能无法正确检测或卸载已安装的证书。
- macOS 默认安装到当前用户的“登录”钥匙串并设置用户级信任；通过 `sudo` 启动时切回原用户操作证书。
- Windows 安装或卸载证书需要管理员权限，具体操作参考[手动安装根证书](../guide/certificate.md)。
